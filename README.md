# Dominion Lens

dominion.gamesの友達・CPU戦向けに作成した日本語Chrome拡張です。既存のDominion Companionのデッキ内訳とドロー確率、Dominion Annotatorのカード情報表示を参考に、独自のコードで実装しました。

## Chromeに追加する

依存パッケージのインストールやビルドは不要です。Chrome 111以降で利用できます。

1. Chromeで `chrome://extensions` を開きます。
2. 右上の「デベロッパーモード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」を押します。
4. このプロジェクトの **extensionフォルダ** を選択します。プロジェクト全体やZIPを選択しないでください。
5. `https://dominion.games/` を再読み込みし、友達またはCPUとの対戦を始めます。

選択するのは、リポジトリを保存した場所にある `extension` フォルダです。右上にパネルが表示されます。「−」ボタンで折りたたみ、同じ位置に現れるボタンで再度開けます。

## 機能

- 所有カードの内訳とアクション・財宝・勝利点の構成比
- アクションエンド・コンボの枚数と割合。所有全体に占める割合と、アクション内の割合を併記
- 全所有カードから5枚引く想定での財宝の期待金量、5金・8金以上になる確率、金量の分布
- 1〜20枚に指定したカードが1枚以上含まれる確率
- 自分の山札・捨て札の内訳。ただし追跡できないときは未確定と表示
- 相手の所有カードの集計と比較
- 基本セット第2版26枚と主要な財宝・勝利点の購入優先度、評価理由
- 購入可能額の手入力による候補の絞り込み
- 日本語の表示、パネルの折りたたみ、表示設定の保存
- 友達・CPU戦の取得済み公開ログを端末に保存し、終了後に履歴から閲覧・削除（初期状態では保存無効）

「所有全体」は手札・山札・捨て札・場・脇に置かれた所有カードを含みます。「王国」は現在のサプライを表示します。デッキ内容、廃棄の需要、追加アクション、呪いの残数、主要な勝利点の残数に応じて評価を調整します。

## 計算と対応範囲

**アクションの分類は、カード自体に記載された「＋アクション」で決めます。** アクションエンドは＋アクションのないカード（鍛冶屋・礼拝堂など）、コンボは＋1アクション以上のカード（村・研究所・市場など）です。「コンボ」はこの拡張での分類名で、相性のよいカードすべてを指すものではありません。玉座の間や家臣は対象・公開カードによって連続使用できますが、自身に＋アクションがないためエンドに分類します。実際のターンに使える回数や、村系カードで使い切れるかを計算する指標ではありません。

分類は基本セット第2版に対応しています。未対応のアクションは「未分類」と表示し、エンド・コンボのどちらにも加えません。ただし所有全体とアクション内の割合の分母には含めます。複合タイプもアクションとして1枚ずつ数えます。アクションが0枚ならアクション内の割合は「—」、所有枚数を確定できない場合は割合を未確定にします。「山札」「捨て札」へ切り替えても、この集計は所有全体を対象にします。

**期待金量は財宝だけのモデルです。** 銅貨1金、銀貨2金、金貨3金、白金貨5金を使い、全所有カードをシャッフルした後の5枚を計算します。アクションから出る金量、追加ドロー、商人の追加金量、コイントークン、実際の手札、プレイ順は含めません。未対応の財宝があれば0金として計算し、「下限」と表示します。

ドロー確率は超幾何分布で求めます。山札を選んだ場合は現在の山札の構成を使いますが、既知の上・下の順番を無視した参考値です。山札と捨て札の内訳が両方確定している場合、山札を使い切るドローでは現在の捨て札をシャッフルして残りの指定枚数を引く2段階モデルへ自動で切り替えます。計算範囲と各段階で引く枚数を画面に表示し、候補とカード枚数には山札・捨て札の両方を含めます。指定枚数が山札枚数以下なら、従来の山札だけの計算と同じです。手札・場・脇のカード、途中のアクション効果や追加の移動はシャッフル対象に含めません。山札と捨て札の合計を超える指定は、引ける枚数までで計算します。どちらかの内訳が未確定ならこのモデルの確率は表示せず、所有全体が確定していれば全所有カードをシャッフルするモデルを案内します。相手の山札・捨て札には適用しません。

評価点は独自のルールに基づく目安で、勝率や最善手の保証ではありません。拡張セットのカードは通常の獲得・廃棄ログから所有枚数を追跡できますが、評価は「未評価」です。特殊なカードの変換、受け渡し、隠された移動などは完全には対応していません。初版の主な検証対象は基本セット第2版です。

## 接続の仕組みと制限

現行サイトの公開クライアント **2.3.4** を調べて、AngularJSの `game` サービスへ接続するアダプターを実装しました。日本語や英語の表示テキストではなく、構造化されたログを読み取ります。開始カードが複数のログ行に分かれていても、全行を加算します。購入と獲得を二重計上せず、巻き戻し後も現在のログから所有枚数を再集計します。

捨て札はクライアントの `CardMove.execute` と `PilesStatus.execute` に観測処理を追加して追跡します。既存のメソッドは元の引数で必ず呼び出し、戻り値を維持します。コマンドを送信したり、ゲームのカード・設定を書き換えたりする機能はありません。

途中参加・再接続・巻き戻しでゲーム状態が作り直された場合、捨て札が空でなければ内訳を未確定にします。捨て札が空になると追跡を再開します。山札は所有カードから手札・場・捨て札・脇のカードを差し引き、ゲームの山札枚数と一致した場合だけ表示します。相手の山札・捨て札の内訳は表示しません。

レート戦では分析表示を停止します。サイトの内部API変更や他の拡張との競合によって、アダプターの修正が必要になる可能性があります。

権限は `storage` とdominion.gamesのコンテンツスクリプトだけです。拡張は外部への通信を行いません。折りたたみ状態、ドロー枚数、基本カードの表示設定を `chrome.storage.local` に保存します。履歴の保存を有効にした場合は、以下の公開情報も同じ端末に保存します。同期ストレージや外部への送信・公開は使いません。履歴の書き込みは拡張のservice workerで順番に処理し、複数タブの保存・削除が競合しないようにしています。追加の権限はありません。

## 対戦ログの履歴

パネルの「履歴」で「対戦ログを端末に保存」を有効にしてください。保存は初期状態では無効です。有効にした時点で取得できる対局ログから記録します。対局終了後の待機画面でも「履歴」を開き、対局IDと日時で選んでログを読めます。ページ再読込やブラウザ再起動後も、同じ拡張のストレージから閲覧できます。

- 保存内容は対局ID、初回・最終取得日時、プレイヤー名、ターン番号、開始カード、購入・獲得・廃棄・交換・公開の受け渡しログとカード名です。プレイヤー名はサイトから取得した表記のまま残ります。
- 自分の手札・山札・捨て札の内訳、非公開の相手の手札、認証情報、チャット、対局スナップショット全体は保存しません。レート戦も保存しません。
- 同じ対局IDは最新の取得ログで置き換えます。再接続で重複を作らず、巻き戻しで取り消された操作は有効な履歴から消えます。全プレイヤーの開始カードログを取得できていない対局には「途中から記録」と表示します。
- 最大30件・合計2 MiBです。件数・容量の上限では最終取得日時が古い履歴から自動削除し、画面で伝えます。1対局だけで容量上限を超えた場合やChromeの保存に失敗した場合は、その更新を未保存と表示し、以前に保存できたログを保持します。「再試行」で現在取得できるログを保存し直せます。
- 個別の「削除」と「全履歴を削除」が使えます。確認後の削除が端末に保存できた場合だけ削除済みと表示します。削除した対局のIDを容量上限内に保持し、ページ再接続・ブラウザ再起動・遅れて届いた更新で履歴が復活しないようにします。削除済みIDだけで容量を使い切った場合は新規記録を停止し、保存を無効にするよう案内します。この場合も既存履歴は閲覧・削除できます。
- 保存を無効にすると、新しい対局と既存対局の更新を保存しません。保存済みの履歴は閲覧・削除できます。拡張を削除すると保存設定・履歴・削除済みIDも失われます。

履歴は拡張が取得できた公開ログだけです。カードの使用やドローなど、保存対象外の行は含みません。ターン番号を取得できない行は「開始時・ターン番号不明」と表示し、長いログは100行ずつページで表示します。日時は取得時刻で、実際の対局開始・終了時刻ではありません。終了への切り替わりでクライアントに最後のログが残っていれば一度取得してから待機表示にしますが、ページを閉じた後や接続が途切れた間の操作は補完できません。

## デモと開発

Node.js 22以降で実行できます。`npm install` は不要です。

```sh
npm run demo
```

`http://127.0.0.1:4173` を開くと、拡張と同じ表示・計算処理を使ったデモが表示されます。銀貨獲得、銅貨廃棄、シャッフル、巻き戻しを試せます。デモは実際の対戦に接続しません。

```sh
npm test
npm run check
npm run package
```

`npm run package` はmacOSなどの `zip` コマンドを使い、`dist/dominion-lens-0.1.1.zip` を生成します。ファイル名の版番号はManifestから取得します。ZIPを別の端末で使う場合は展開し、`manifest.json` の入ったフォルダをChromeに読み込んでください。

PRを作成・更新すると、GitHub Actionsの「PR validation」がNode.js 22で上記3コマンドを実行し、`unzip -t` でZIPの整合性を検査します。テストの同時実行は2プロセスまでです。CIではChromeの起動コマンドとテストのスキップが0件であることも確認します。PRのChecksから各ステップの結果と失敗ログを確認できます。すべて成功した場合は、その実行のArtifactsから版番号付きのZIPを7日間ダウンロードできます。依存パッケージのインストールは行わず、ワークフローの権限はリポジトリの読み取りだけです。

## 検証状況

- 自動テスト：分割された開始カードログと廃棄・巻き戻し、アクションの分類と割合・未分類・0枚時の扱い、金量の分布、ドロー確率・捨て札シャッフル・未確定時の表示、獲得・廃棄・交換・受け渡し、途中参加、捨て札の追跡、サイトアダプター、レート戦停止、不正なデータの拒否、空サプライの表示、数値入力・フォーカス移動中の更新
- 履歴の自動テスト：保存切り替え、同一対局の重複防止、巻き戻し、終了直前のログ取得、削除との競合、件数・容量上限、保存失敗、破損データの拒否、保存項目の制限を検証。全70件成功・skip 0
- Manifest V3、権限、参照ファイル、JavaScriptの構文を検査
- ブラウザのデモでアクションの割合・プレイヤー切り替え・獲得・廃棄・巻き戻し・山札・王国評価・購入可能額フィルターを確認
- 独立した一時Chromeプロファイルに実拡張を読み込み、匿名のCPU・友達fixtureで履歴の閲覧、ページ再読込、Chrome再起動、個別・全削除後の再記録防止、未保存表示と再試行、HTMLのエスケープ、長いログのページ送りを確認。対局サイトへの通信はテスト内で遮断し、動作中のChromeには接続しない
- **ログイン後の実際のCPU戦・友達との対戦は未検証**。初回導入時に確認が必要です

実対戦での確認項目は `docs/live-check.md`、履歴の受け入れ条件ごとの検証と制約は `docs/history-check.md` にあります。
