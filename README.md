# Dominion Lens

dominion.gamesの友達・CPU戦向けに作成した日本語Chrome拡張です。既存のDominion Companionのデッキ内訳とドロー確率、Dominion Annotatorのカード情報表示を参考に、独自のコードで実装しました。

[初めて追加する](#chromeに追加する) · [更新する](#更新する) · [適用版を確認する](#適用版を確認する)

## Chromeに追加する

依存パッケージのインストールやビルドは不要です。Chrome 111以降で利用できます。

1. Chromeで `chrome://extensions` を開きます。
2. 右上の「デベロッパーモード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」を押します。
4. **manifest.jsonが直接入っているフォルダ** を選択します。Gitのcheckoutなら `extension` フォルダです。プロジェクト全体やZIPを選択しないでください。
5. `https://dominion.games/` を再読み込みし、友達またはCPUとの対戦を始めます。

Gitで取得した場合はリポジトリ内の `extension` フォルダを選びます。GitHubの「Code → Download ZIP」は展開先の `dominion-lens-main/extension`、配布用の `dominion-lens-<版番号>-<build識別子>.zip` は展開先で `manifest.json` が直接入っているフォルダを選びます。どの場合も、選んだフォルダの絶対パスを控えてください。

右上にパネルが表示されます。「−」ボタンで折りたたみ、同じ位置に現れるボタンで再度開けます。導入後は[適用版の確認](#適用版を確認する)と[実対戦での確認](docs/live-check.md)へ進んでください。

## 更新する

対戦を終えてから、次の順に手動で操作してください。ソースの更新だけでは、Chrome内の拡張や既存のゲームページは更新されません。この拡張が対戦やページを自動で再読み込みすることはありません。

### 1. Chromeが読み込むフォルダを確認してソースを更新する

`chrome://extensions` でデベロッパーモードを有効にし、Dominion Lensの「詳細」にある読み込み元のパスを確認します。導入時に控えたパスとも照合してください。別のcheckoutや展開コピーを更新しても、読み込み元は更新されません。

**Gitを使う場合**は、その読み込み元が所属するリポジトリのルートで実行します。

```sh
git remote -v
git status
git branch --show-current
```

originが `oXyut/dominion-lens`、ブランチが `main`、作業中の変更がないことを確認してから、次を実行します。

```sh
git pull --ff-only origin main
git log -1 --oneline
```

変更がある、別のブランチを使っている、競合や分岐でpullが失敗する場合はここで止め、`git status` とエラーの内容を確認してください。作業中の変更を退避する方法やブランチの状況を確認するまでは、強制resetやファイルの削除をしないでください。

**ZIPを使う場合**は、新しいZIPを別の空フォルダへ展開します。Code → Download ZIPならその中の `extension`、配布ZIPなら `manifest.json` が直接入っているフォルダが更新元です。版番号とbuild識別子を[次の確認方法](#適用版を確認する)で確認してから、Chromeの読み込み元フォルダの内容を、新しい更新元の内容一式と入れ替えてください。上書きだけで古いファイルを残さず、実際の読み込み元パスを保ちます。ZIPを再ダウンロードするだけ、別の場所に展開するだけでは更新されません。

読み込み元が分からない場合や展開先を変更したい場合は、対戦終了後に古いDominion LensをChromeから削除し、「パッケージ化されていない拡張機能を読み込む」で新しいフォルダを指定します。削除すると拡張の表示設定も失われます。以後の更新用に新しいパスを控えてください。

### 2. Chromeの拡張を再読み込みする

`chrome://extensions` に戻り、Dominion Lensの再読み込みボタンを押します。「詳細」の版表示を、読み込み元の `manifest.json` の `version_name`（版番号とbuild識別子）と照合してください。Chromeが版番号だけを表示する場所では `version` と照合します。この操作で既存のゲームページのコードまで更新されるとは限りません。

### 3. 既存のゲームページを再読み込みする

dominion.gamesを開いているタブを手動で再読み込みします。複数のゲームタブを使っている場合は、それぞれ再読み込みしてください。パネルを開き、下端の版番号とbuild識別子を読み込み元のManifestと照合します。古い版が残る場合は、読み込み元のパス、ソース更新、拡張の再読み込み、ページの再読み込みを順に確認してください。

### 4. 新しい対戦で確認する

基本セット第2版のCPU戦を新しく始め、銅貨7枚・屋敷3枚の初期10枚と期待金量3.50金を確認します。続いて礼拝堂や改築などによる通常の屋敷廃棄で、所有枚数が減り、「ログにないカードの移動があり」という警告が出ないことを確認します。[実対戦での確認](docs/live-check.md)の項目3・5を参照してください。

## 適用版を確認する

0.1.2以降は、次の3か所を対応付けます。build識別子は拡張ソースのSHA-256から作る12桁の識別子で、Gitのcommit SHAとは別です。同じ版番号でもソースが変われば識別子が変わります。

| 確認場所 | 表示・記載内容 |
| --- | --- |
| ゲームページのパネル下端 | `v0.1.2 · <build識別子>` |
| Chromeの読み込み元にある `manifest.json` | `version` は `0.1.2`、`version_name` は `0.1.2 (<build識別子>)` |
| 配布ZIPのファイル名 | `dominion-lens-0.1.2-<build識別子>.zip` |

パネルはそのページで読み込んだコードの版を表示します。ソースや拡張だけを更新しても、既存ページの表示は新しい版の証拠になりません。パネル・読み込み元のManifest・配布ZIPの識別子が一致することを確認してください。Code → Download ZIPのファイル名には識別子がないため、展開後のManifestで確認します。0.1.1の表示しかない古いコピーでは修正適用を判別できないので、上の更新手順を実施してください。

## 機能

- 所有カードの内訳とアクション・財宝・勝利点の構成比
- アクションエンド・コンボの枚数と割合。所有全体に占める割合と、アクション内の割合を併記
- 全所有カードから5枚引く想定での財宝の期待金量、5金・8金以上になる確率、金量の分布
- 1〜20枚に指定したカードが1枚以上含まれる確率
- 自分の山札・捨て札の内訳。ただし追跡できないときは未確定と表示
- 相手の所有カードの集計と比較
- 基本セット第2版26枚と主要な財宝・勝利点の購入優先度、評価理由
- 購入可能額の手入力による候補の絞り込み
- 日本語の表示、パネルの折りたたみ、表示設定の保存

「所有全体」は手札・山札・捨て札・場・脇に置かれた所有カードを含みます。「王国」は現在のサプライを表示します。デッキ内容、廃棄の需要、追加アクション、呪いの残数、主要な勝利点の残数に応じて評価を調整します。

## 計算と対応範囲

**アクションの分類は、カード自体に記載された「＋アクション」で決めます。** アクションエンドは＋アクションのないカード（鍛冶屋・礼拝堂など）、コンボは＋1アクション以上のカード（村・研究所・市場など）です。「コンボ」はこの拡張での分類名で、相性のよいカードすべてを指すものではありません。玉座の間や家臣は対象・公開カードによって連続使用できますが、自身に＋アクションがないためエンドに分類します。実際のターンに使える回数や、村系カードで使い切れるかを計算する指標ではありません。

分類は基本セット第2版に対応しています。未対応のアクションは「未分類」と表示し、エンド・コンボのどちらにも加えません。ただし所有全体とアクション内の割合の分母には含めます。複合タイプもアクションとして1枚ずつ数えます。アクションが0枚ならアクション内の割合は「—」、所有枚数を確定できない場合は割合を未確定にします。「山札」「捨て札」へ切り替えても、この集計は所有全体を対象にします。

**期待金量は財宝だけのモデルです。** 銅貨1金、銀貨2金、金貨3金、白金貨5金を使い、全所有カードをシャッフルした後の5枚を計算します。アクションから出る金量、追加ドロー、商人の追加金量、コイントークン、実際の手札、プレイ順は含めません。未対応の財宝があれば0金として計算し、「下限」と表示します。

ドロー確率は超幾何分布で求めます。山札を選んだ場合は現在の山札の構成を使いますが、既知の上・下の順番を無視した参考値です。山札と捨て札の内訳が両方確定している場合、山札を使い切るドローでは現在の捨て札をシャッフルして残りの指定枚数を引く2段階モデルへ自動で切り替えます。計算範囲と各段階で引く枚数を画面に表示し、候補とカード枚数には山札・捨て札の両方を含めます。指定枚数が山札枚数以下なら、従来の山札だけの計算と同じです。手札・場・脇のカード、途中のアクション効果や追加の移動はシャッフル対象に含めません。山札と捨て札の合計を超える指定は、引ける枚数までで計算します。どちらかの内訳が未確定ならこのモデルの確率は表示せず、所有全体が確定していれば全所有カードをシャッフルするモデルを案内します。相手の山札・捨て札には適用しません。

評価点は独自のルールに基づく目安で、勝率や最善手の保証ではありません。拡張セットのカードは通常の獲得・廃棄ログから所有枚数を追跡できますが、評価は「未評価」です。特殊なカードの変換、受け渡し、隠された移動などは完全には対応していません。初版の主な検証対象は基本セット第2版です。

## 接続の仕組みと制限

現行サイトの公開クライアント **2.3.4** を調べて、AngularJSの `game` サービスへ接続するアダプターを実装しました。日本語や英語の表示テキストではなく、構造化されたログを読み取ります。開始カードが複数のログ行に分かれていても、全行を加算します。購入と獲得を二重計上せず、巻き戻し後も現在のログから所有枚数を再集計します。

捨て札はクライアントの `CardMove.execute` と `PilesStatus.execute` に観測処理を追加して追跡します。既存のメソッドは元の引数で必ず呼び出し、戻り値を維持します。コマンドを送信したり、ゲームのカード・設定を書き換えたりする機能はありません。

途中参加・再接続・巻き戻しでゲーム状態が作り直された場合、捨て札が空でなければ内訳を未確定にします。捨て札が空になると追跡を再開します。山札は所有カードから手札・場・捨て札・脇のカードを差し引き、ゲームの山札枚数と一致した場合だけ表示します。相手の山札・捨て札の内訳は表示しません。

レート戦では分析表示を停止します。サイトの内部API変更や他の拡張との競合によって、アダプターの修正が必要になる可能性があります。

権限は `storage` とdominion.gamesのコンテンツスクリプトだけです。拡張は外部への通信を行いません。保存するのは折りたたみ状態、ドロー枚数、基本カードの表示設定だけです。ゲームID、対戦ログ、プレイヤー名は保存しません。

## デモと開発

Node.js 22以降で実行できます。`npm install` は不要です。

配布済みのソースにはbuild情報を同梱しているため、初回導入や通常の更新にビルドは不要です。開発で `extension` 内のソースや版番号を変更した場合は、検証前に次を実行し、生成された `extension/lib/build-info.js` とManifestの `version_name` もcommitしてください。版番号を変える場合は `package.json` とManifestの `version` を揃えます。

```sh
npm run build:info
```

`npm run check` と `npm run package` はソースとbuild情報が一致しなければ失敗します。複数の変更を統合した場合も、統合後のソースからbuild情報を再生成してください。

```sh
npm run demo
```

`http://127.0.0.1:4173` を開くと、拡張と同じ表示・計算処理を使ったデモが表示されます。銀貨獲得、銅貨廃棄、シャッフル、巻き戻しを試せます。デモは実際の対戦に接続しません。

```sh
npm test
npm run check
npm run package
```

`npm run package` はmacOSなどの `zip` コマンドを使い、`dist/dominion-lens-<版番号>-<build識別子>.zip` を生成します。版番号とbuild識別子は検証済みのManifest・build情報と一致します。ZIPを別の端末で使う場合は展開し、`manifest.json` の入ったフォルダをChromeに読み込んでください。

PRを作成・更新すると、GitHub Actionsの「PR validation」がNode.js 22で上記3コマンドを実行し、`unzip -t` でZIPの整合性を検査します。テストの同時実行は2プロセスまでです。CIではChromeの起動コマンドとテストのスキップが0件であることも確認します。PRのChecksから各ステップの結果と失敗ログを確認できます。すべて成功した場合は、その実行のArtifactsから版番号付きのZIPを7日間ダウンロードできます。依存パッケージのインストールは行わず、ワークフローの権限はリポジトリの読み取りだけです。
