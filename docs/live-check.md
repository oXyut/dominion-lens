# 実対戦での確認

この初版は公開クライアント2.3.4の構造と同じインターフェースを持つテスト用モデル、ブラウザ上のデモで検証しています。以下の実対戦の項目はまだ未確認です。

更新後の確認では、先に[READMEの更新手順](../README.md#更新する)に沿って、対戦終了後に読み込み元のソース更新、Chromeの拡張再読み込み、既存ゲームページの再読み込みを順に実施します。パネル下端の版番号・build識別子が読み込み元のManifestと一致したら、新しいCPU戦で下の項目3（初期10枚・期待3.50金）と項目5（通常の屋敷廃棄）を確認してください。確認のために進行中の対戦を再読み込みしないでください。

1. 拡張をChromeに追加し、dominion.gamesを再読み込みする。
2. 基本セット第2版のCPU戦を新しく始める。
3. 開始カードが屋敷と銅貨の別々のログ行になっていても、「所有全体」が銅貨7枚・屋敷3枚の合計10枚、期待金量3.50金になることを確認する。
4. 銀貨を買い、合計11枚・銀貨1枚になることを確認する。2枚増えていないことも確認する。
5. 礼拝堂や改築などで屋敷を廃棄し、所有枚数が減ることを確認する。「ログにないカードの移動があり」という警告が出ないことも確認する。
6. 「捨て札」で購入カードとターン終了時の手札・場のカードが加算されることを確認する。
7. シャッフル後に捨て札が空になり、山札の枚数がゲーム画面と一致することを確認する。
8. 巻き戻しを行い、所有全体が元に戻ることを確認する。捨て札の内訳が未確定になる場合、次に空になるまで待つ。
9. 王国評価で、呪いが空になったときに魔女の優先度が下がることを確認する。
10. ゲーム終了後に次のCPU戦を始め、前のデッキが残らないことを確認する。
11. 日本語・英語の両方の表示言語で追跡する。
12. 友達との非レート戦でも同じ項目を確認する。
13. 初期デッキのアクションエンド・コンボが各0枚・所有全体0.0%、アクション内は「—」になることを確認する。
14. 新しく始めた10枚の初期デッキに鍛冶屋と村を各1枚獲得し、各1枚・所有全体8.3%（12枚中1枚）・アクション内50.0%になることを確認する。廃棄・巻き戻し後も割合が更新されることを確認する。
15. プレイヤーを相手に切り替え、相手の所有カードから割合を計算していることを確認する。「山札」「捨て札」への切り替えでは割合の対象が所有全体のままであることを確認する。
16. 拡張セットのアクションを含む場合、未対応のカードが「未分類」となり、エンド・コンボの割合が未分類を含めた分母で計算されることを確認する。

問題が起きた場合は、Chromeの拡張機能ページでこの拡張の「エラー」を確認してください。表示が古い場合は、対戦終了後に[READMEの更新手順](../README.md#更新する)で読み込み元と適用版を確認します。再読み込み直後の捨て札が未確定になることはあります。
